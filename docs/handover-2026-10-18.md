## 6. How the session ran (keep doing this)
- One fresh agent per unit, **always Opus** (`model: "opus"`), at most four at once (D-036), each in a harness worktree (`isolation: worktree`): the agent checks out or creates the change branch inside it, runs `git lfs checkout`, works, commits, does not push. After the handoff: remove the worktree, prune, delete the `worktree-agent-<id>` branch, push the lane branch from the main checkout.
- Subagent shells may not carry `$env:UNITY` / `$env:BLENDER`: the briefs give the literal paths. Unity Hub must be running; `Unity.exe` is piped with `| Out-Host`. Run the tests as `python -m pytest tools -q` (the folders' conftests clash when given separately). Builds with shell fits or the S04 audit take minutes: background, never polled.
- **Each agent keeps scratch files in its own scratchpad subfolder** and deletes only that; **never `taskkill /IM`** (one agent killed another's python). Look tasks read the letters only in the main checkout's `reference/_frames/<letter>/sheets/`, write side-by-sides only to `reference/_compare/` (git-ignored), never open `index.md`, `letters.md` or a clip.
- Orchestrator edits to a lane branch (settling a QA or physics question, a tasks line) go through a scratchpad worktree: `git worktree add <scratchpad>/wt <branch>`, edit (a Python script file when the text is long: bash heredocs with quotes break), commit as Orchestrator, remove the worktree, push.
- Planning artefacts and archives land on `unity/main` through `unity/chore/*` branches and PRs the orchestrator opens and merges at once. `openspec archive <id> -y` syncs the deltas; stage the removed folder with `git add -u`.
- QA verdicts are followed to the letter; owner readings (physics on metadata) run when a change brings a new contract, and their S-items go into the spec before the asset-artist builds. The orchestrator settles only what they ask (R5, R7, R10–R11, S04's 14a–c this session) and records it.
- A crashed session: `git worktree list`; a locked agent worktree with uncommitted work was resumed once by `SendMessage` to its agent id within the same session. A new session cannot: read the worktree's commits and diff, and respawn the task from the tip.
