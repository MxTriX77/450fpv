## How the session ran (keep doing this)
- One fresh agent per task, at most two at once, each in a harness worktree (`isolation: worktree`): the agent checks out or creates the change branch inside it, runs `git lfs checkout`, works, commits, does not push. After the handoff: `git worktree remove --force <path>`, `git worktree prune`, delete the `worktree-agent-<id>` branch, then push the role branch from the main checkout. If a folder is "busy", `git -C <path> checkout --detach` frees the branch.
- Subagent shells may not carry `$env:UNITY` / `$env:BLENDER`: the briefs give the literal paths (now in `docs/environment.md`).
- Orchestrator edits to a role branch (settling a QA question in `docs/decisions.md`, a tasks line) go through a scratchpad worktree: `git worktree add <scratchpad>/wt <branch>`, edit, commit as Orchestrator, `git worktree remove`.
- Planning artefacts and archives land on `unity/main` through `unity/chore/*` branches and PRs; `openspec archive <id> -y` syncs the deltas; **stage the removed change folder too** (`git add -u openspec/changes/<id>`), or the old folder stays in the tree (PR #63 fixed that once).
- QA verdicts are followed to the letter; the orchestrator only settles the decisions QA asks for (R5, R7, R10–R11 this session) and records them in `docs/decisions.md` or the requirement text.
